# State.io — Территория решает

Браузерная стратегия с кампанией и онлайн-битвами с друзьями: территории выращивают гарнизоны, отряды захватывают земли и подкрепляют союзников. Оригинальный интерфейс и программно построенные карты; проект не использует ресурсы оригинальной игры.

## Возможности

- Кампания из 1000 детерминированных карт: шесть форм и планировок, острова, кольцо, алмазный материк, длинный берег, звёздные острова и земли севера. До трёх AI-соперников, три сложности; выбор уровней по страницам из 25 операций.
- Отправка 100% целого гарнизона на момент команды, отдельный шарик для каждого бойца, максимум четыре вылета каждые 0,1 секунды с каждой базы. Гарнизон убывает при вылете; новобранцы остаются на базе. Повторная команда меняет цель оставшейся армии. При захвате базы её очередь отменяется.
- Бойцы летят в 3,5 раза быстрее предыдущей версии. Вражеские бойцы уничтожают друг друга один к одному при встрече в воздухе, включая пересечения разных маршрутов; союзники проходят свободно. Проверяется весь пройденный за шаг отрезок, чтобы быстрые бойцы не пролетали сквозь друг друга. Движок использует одинаковые траектории в кампании, мультиплеере и на обоих типах экрана.
- Интеллект ботов растёт с уровнем: от медленных, ошибающихся новичков к прогнозированию подкреплений и роста гарнизона, встречным перехватам, защите угрожаемых баз и совместным атакам. Первый уровень выигрывается одной прямой атакой. К 1000-му боты реагируют за 0,16 секунды на обычной сложности, начинают с 999 бойцами на каждой из трёх баз и получают до 25-кратного множителя роста. Финал рассчитан на практически непреодолимое сопротивление; это игровой баланс, а не формальная гарантия невозможности победы при любой стратегии.
- Онлайн-комнаты на 2–4 аккаунта: создай комнату, выбери карту, передай код друзьям и начни битву. Без AI; сервер рассчитывает армию, движение, столкновения и победителя, проверяет владельца отправляющих территорий. Все игроки получают одинаковые стартовые гарнизоны и рост баз.
- Нажатия, перетаскивание, Shift для выбора нескольких баз, управление клавиатурой.
- Адаптивный интерфейс: горизонтальная карта на компьютере, вертикальная на телефоне; SVG остаётся чётким при любом разрешении.
- Регистрация по email и паролю, вход и выход, 30-дневные сессии в HttpOnly cookie.
- Серверные сохранения кампании, текущей партии, движущихся бойцов, очередей вылета, личного времени и настроек. Автосохранение каждые 15 секунд и при паузе/скрытии вкладки; при загрузке партия всегда на паузе. Сохранения предыдущих версий сохраняют геометрию карты и армию в пути; старые объединённые отряды преобразуются в отдельных бойцов с новой скоростью. Сложность AI следует уровню и обновляется также в ранее сохранённых партиях.
- Продолжение с другого устройства через тот же сервер и аккаунт. Версии обновляются атомарно: конфликт требует явного выбора, перед заменой облачного сохранения есть подтверждение.
- Гостевые партии сохраняются в браузере; можно перенести прогресс при создании аккаунта. При отсутствии сети последняя партия остаётся локально и синхронизируется после восстановления связи.
- Без npm-зависимостей, внешних шрифтов, аналитики и CDN.

## Локальный запуск

Нужен **Node.js 24 LTS**. Установка npm-пакетов не требуется.

```sh
node server.mjs
# Открыть именно http://localhost:3000 (origin проверяется при записи).
node --test tests/*.test.mjs
```

Сервер по умолчанию слушает `127.0.0.1:3000`. База создаётся в `data/game.sqlite`. Настройки задаются переменными окружения; `.env` автоматически не загружается. Пример — `.env.example`.

Для телефона в локальной сети временно задайте `HOST=0.0.0.0` и `APP_ORIGIN=http://<IP-компьютера>:3000`; используйте этот адрес на обоих устройствах. В production обязателен HTTPS.

## Развёртывание на чистом сервере

Поддерживаются **Ubuntu 22.04+ / Debian 12+**, systemd, x86_64 и arm64. Нужны root/sudo, исходящие соединения для apt/Node.js/Let's Encrypt и домен, направленный A/AAAA-записями на сервер. Откройте входящие TCP 80 и 443 в панели провайдера; SSH оставьте доступным. Если AAAA-запись существует, IPv6 также должен работать.

Скопируйте весь проект на сервер, например в `/root/state-io-source`, затем выполните:

```sh
cd /root/state-io-source
sudo bash deploy.sh game.example.com admin@example.com
```

Если используете подготовленный архив, сначала распакуйте его:

```sh
mkdir -p /root/state-io-source
tar -xzf state-io.tar.gz -C /root/state-io-source
cd /root/state-io-source
sudo bash deploy.sh game.example.com admin@example.com
```

Скрипт устанавливает пакеты, официальный Node.js 24 с проверкой SHA256, отдельного пользователя `stateio`, приложение, systemd-сервис, Nginx, сертификат и продление HTTPS, ежедневные онлайн-бэкапы SQLite. Скрипт не изменяет настройки SSH и не включает firewall; если UFW уже активен, разрешает профиль Nginx Full.

Email для Let's Encrypt необязателен: `sudo bash deploy.sh game.example.com`. В этом случае сертификат и автопродление работают, но email-уведомления не настроены. Позднее можно добавить адрес командой `sudo certbot update_account --email ваш-email`.

Код релизов: `/opt/state-io/releases/`, активный релиз: `/opt/state-io/current`. Сервис работает без root, код доступен только для чтения. Данные всегда остаются в `/var/lib/state-io/game.sqlite`, независимо от релиза. Порт приложения доступен только локально через Nginx. Публичный адрес записывается в `/etc/state-io/app.env`.

Повторный запуск скрипта из отдельной папки с обновлённым проектом создаёт новый релиз и резервную копию базы. Старые релизы сохраняются. При провале проверки запуска приложение переключается на предыдущий релиз; HTTPS/DNS-ошибки требуют исправить записи/порты и повторить скрипт. Скрипт управляет `/etc/nginx/sites-available/state-io.conf`: используйте его для одного экземпляра приложения на сервере.

Для `divvyspace.ru` на чистом сервере: `sudo bash deploy.sh divvyspace.ru`. Если уже работает Caddy или другой HTTPS-прокси, используй `sudo bash deploy.sh divvyspace.ru --existing-proxy`: установщик развернёт приложение и бэкапы, сохранив текущий прокси. Маршрут и HTTPS в этом режиме настрой в существующем прокси. При активном Caddy стандартный режим останавливается до изменений, чтобы не занимать его порты.

Пример блока в существующем Caddyfile (добавь к своей конфигурации, сохранив остальные сайты):

```caddyfile
divvyspace.ru {
    reverse_proxy 127.0.0.1:3000 {
        header_up X-Real-IP {remote_host}
    }
}
```

Проверь конфигурацию `sudo caddy validate --config /etc/caddy/Caddyfile`, затем `sudo systemctl reload caddy`. Caddy передаёт `text/event-stream` сразу по [своей документации](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#streaming); отдельный `flush_interval -1` не нужен. В Nginx установщик отключает буферизацию SSE и разрешает сохранения до 1,5 МБ. Другой прокси тоже должен пропускать `text/event-stream` без буферизации, с таймаутом чтения не меньше 75 секунд.

```sh
sudo systemctl status state-io
sudo journalctl -u state-io -f
sudo systemctl restart state-io
sudo systemctl status state-io-backup.timer
sudo certbot renew --dry-run
```

## Резервные копии и восстановление

Бэкапы содержат аккаунты, хеши паролей, сессии и сохранения. Храните их закрыто и регулярно копируйте на другой сервер. Ежедневные копии старше 14 дней удаляются; копии перед развёртыванием сохраняются.

```sh
sudo systemctl start state-io-backup.service
# Выберите реальный файл из /var/lib/state-io/backups и подставьте его путь:
sudo systemctl stop state-io
sudo -u stateio sqlite3 /var/lib/state-io/game.sqlite ".restore '/var/lib/state-io/backups/ИМЯ_КОПИИ.sqlite'"
sudo systemctl start state-io
```

Не копируйте один основной `.sqlite` файл при запущенном сервере: журнал WAL может содержать последние изменения. Используйте штатный `.backup`. Для отката кода переключите `/opt/state-io/current` на нужный сохранённый каталог релиза и перезапустите сервис. При будущих изменениях схемы отдельно учитывайте совместимость базы.

## Безопасность и ограничения

Пароли: PBKDF2-HMAC-SHA256, 600 000 итераций и случайная соль; параметры соответствуют [рекомендации OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). Сессии — криптографические токены, в БД хранятся только их SHA256-хеши. Есть ограничение попыток входа по IP и email, проверка origin, подготовленные SQL-запросы, лимит тела запроса, проверка структуры сохранения и security headers. Production cookie требует HTTPS. Email служит логином: в этой версии нет SMTP, проверки email и восстановления пароля.

Одиночная кампания рассчитывается на клиенте; сервер проверяет структуру сохранения и изоляцию аккаунтов, но не доказывает честность каждой победы в кампании. Онлайн-битвы рассчитываются только на сервере: команды передаются через POST, состояние — через SSE, движение отображается каждый кадр с интерполяцией. Публичной соревновательной таблицы нет.

Комнаты хранятся в памяти одного процесса; перезапуск приложения завершает онлайн-битвы. Кампания и аккаунты остаются в SQLite. В онлайн-битве нет паузы: при потере сети у игрока есть 90 секунд на возвращение, в том числе через тот же аккаунт на другом устройстве. Затем его армия выходит из боя, территории становятся нейтральными. Лобби без подключения освобождается через пять минут, завершённая комната — через десять. Выход во время битвы означает сдачу. Кампания сохраняется отдельно и восстанавливается после выхода из комнаты.

SQLite и один процесс рассчитаны на небольшой/средний сервер (максимум 40 одновременных комнат). Для нескольких реплик потребуется общая БД и координация матчей. Онлайн-сохранения разных серверов не объединяются.

## Файлы

- `server.mjs` — HTTP, аккаунты, SQLite, API и static assets.
- `multiplayer.mjs` — комнаты, серверная симуляция, проверка команд, SSE и переподключение.
- `public/engine.js` — симуляция, AI, генератор карт, проверка сохранений.
- `public/app.js` — интерфейс, SVG-карта и синхронизация.
- `public/style.css` — адаптивная раскладка.
- `deploy.sh` — полный установщик собственного сервера.
- `tests/` — тесты движка, безопасности API и сохранений между сессиями.

## Проверка

```sh
node --check server.mjs
node --check multiplayer.mjs
node --check public/app.js
node --check public/engine.js
node --test tests/*.test.mjs
bash -n deploy.sh
```

Тесты запускают отдельный сервер с временной SQLite, не затрагивая пользовательские аккаунты. Проверяйте DNS/HTTPS и установку systemd на целевом сервере: они зависят от его окружения.

Для версии 1.2 прошли все 34 теста: карты всех 1000 уровней, ускорение бойцов, столкновения встречных потоков и пересекающихся маршрутов между кадрами, потери один к одному, совместимость сохранений, координация и перехваты AI, лёгкая победа на первом уровне и поражение двух тестовых стратегий на 1000-м во всех сложностях. Также проверены аккаунты, сохранения между сессиями, серверный онлайн-бой, комнаты на четыре игрока, чужие команды и переподключение. В браузере проверены 1440×810 (16:9) и 390×867 (20:9), страницы кампании, отображение уровня 1000, победа на первом уровне и атаки финальных ботов. Установщик прошёл `bash -n`. Полная установка на Linux и выпуск реального сертификата в этой среде не выполнялись.
